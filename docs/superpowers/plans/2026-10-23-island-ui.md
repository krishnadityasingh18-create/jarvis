# JARVIS Island UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the floating island + expanded panel (Electron), the Vault, the Artifacts list, and WhatsApp from the user's own number, as specified.

**Architecture:** The Python backend stays the core; it gains vault/artifact/glance/fullscreen/mic-level data over the existing `/ws` socket and serves a new `/island` page. A fixed-size transparent Electron window shows that page above every app. A small Node helper (Baileys) links the user's WhatsApp and is called by `send_whatsapp`.

**Tech Stack:** Python 3.13 / FastAPI / SQLite / pytest (existing); Electron 33.x; Node 24 with `@whiskeysockets/baileys` 6.7.x and `node:test`; anime.js v4 (already in `jarvis/ui/`); Playwright (Python package, dev only) for the UI check.

**Spec:** `docs/superpowers/specs/2026-10-23-island-ui-design.md`. **Mockup:** `docs/superpowers/specs/assets/2026-10-23-island-mockup.html`. The mockup is the visual source of truth (sizes, colours, spring values, CSS); port from it, don't redesign.

## Global Constraints

- Free only: no paid services or packages. No secrets in code; keys stay in Windows Credential Manager via `jarvis.config.get_key/set_key`.
- Nothing permanent: removals go to `data/trash` with an undo record; never delete user files.
- Never send anything outward without the user's confirmation; WhatsApp sends always confirm and are blocked on remote channels (`ctx.remote`).
- `data/wa_auth/`, `data/wa/`, `desktop/node_modules/`, `desktop/wa/node_modules/` are gitignored.
- Island window: fixed 560×660, transparent, frameless, always on top (`'screen-saver'`), `focusable: false` + `showInactive()`, `type: 'toolbar'`, `backgroundThrottling: false`; never resized or moved during animation.
- Springs (mass 1, stiffness=(2π/d)², damping=(1−bounce)·4π/d): expand 0.5 s/0.15, collapse 0.42 s/0, micro 0.3 s/0.1, drop 0.55 s/0.3.
- The orb never pulses (no scale change with mic level). Listening = cool hue + 7-bar meter; thinking = warm hue + shimmer "Thinking" + comet looping the edge until thinking ends.
- Follow existing idiom: tools are `@tool(...)` functions returning `(result, undo)`; tests are plain pytest with `cfg`/`conn` fixtures and `tests.test_tools.make_ctx/call`.
- Run the suite with `.venv\Scripts\python -m pytest -q`; it must stay green (383 at plan time).

## WebSocket contract (Phases A, B, D share this)

Server → client (new):
- `{"type":"vault","items":[{"id":int,"kind":"note"|"link"|"file","title":str,"text":str,"path":str,"url":str,"ts":str}]}` — sent on connect and after any vault change.
- `{"type":"artifacts","items":[{"id":int,"kind":"document"|"research"|"commit"|"file","title":str,"path":str,"preview":str,"ts":str,"exists":bool}]}` — on connect and after each `turn_end`.
- `{"type":"glance","items":[{"icon":"sun"|"cal"|"check"|"mail"|"bell","value":str,"detail":str,"at":str}]}` — on connect, every 15 min, and after reminder changes. `bell` items are reminders due within 60 min, with `at` (ISO) so the island can show a countdown bubble in the last 10 min; `at` is `""` for other icons.
- `{"type":"tool_start","name":str}` — emitted by `tools.run` just before a tool executes; the island shows a live-activity bubble for `ask_claude` and `send_whatsapp` until the matching `action` message arrives.
- `{"type":"fullscreen","on":bool}` — on change.
- `{"type":"mic_level","level":float}` — 0..1, ≤15/s, only while listening.
- `{"type":"notify","icon":"whatsapp"|"reminder","title":str,"text":str}` — drop-down card.
- `{"type":"whatsapp","state":"linked"|"unlinked"|"qr","qr":str}` — `qr` is a data: URL when state is `qr`.

Client → server (new):
- `{"type":"keep","text":str}` or `{"type":"keep","name":str,"data":base64}` — drag-to-vault after the island's own "Keep in vault?" card.
- `{"type":"open_item","kind":"vault"|"artifact","id":int}` — opens in the default app; the server looks the path up by id (never trusts a path from the page).
- `{"type":"remove_vault","id":int}`
- `{"type":"full_view"}` — open the Edge HUD.
- `{"type":"whatsapp_link"}` — start linking; the server replies with `whatsapp` messages.

Existing messages are unchanged; chat chips reuse `open_chat` (no new `chat_load`).

## Review Focus

1. A path or URL dragged in twice → vault keeps one item per identical file (same sha256) or text, and says "already in your vault".
2. A WhatsApp name that matches two contacts ("Rahul") → asks which; never picks one. A name that matches none → asks for the number; never guesses.
3. The page sending `open_item` for an id that doesn't exist or whose file is gone → "moved or deleted" banner, nothing opened.
4. The helper not running / crashed mid-send → `send_whatsapp` says it failed, never "sent".
5. Mic level messages arriving after listening ended → ignored by the UI (meter only reads them in `st-listening`).
